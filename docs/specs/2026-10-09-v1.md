# daylog v1 — spec

Goal: a version he can use **today**. Refinement comes from using it. Vision lives in
`docs/vision.md`; this file is what v1 commits to.

## Pieces

| Piece | Tech | Runs as |
|---|---|---|
| Backend: HTTP API + event log | Python, FastAPI, SQLite | launchd agent `com.rithvik.daylog.server` on `127.0.0.1:7878` |
| Side button + panel + activity recorder | Swift, AppKit + SwiftUI | launchd agent `com.rithvik.daylog.app` (`~/Applications/Daylog.app`) |
| MCP server | Python, FastMCP (stdio), calls the HTTP API | started by each agent client (registered in Claude Code, user scope) |
| Wispr importer | Python, reads Wispr's SQLite read-only | runs inside the server every 10 min |

## Data: one append-only table

`events` is the system of record. **A SQLite trigger rejects every UPDATE and DELETE**,
which enforces the rule in code, not by convention. Every view (timeline, summary,
"now") is *derived* from events at read time.

| column | meaning |
|---|---|
| `id` | uuid |
| `recorded_at` | when the backend wrote it (UTC) |
| `kind` | `claim` (he said it) or `observation` (a machine saw it) |
| `type` | `timer.start`, `timer.stop`, `entry.log`, `entry.delete`, `app.focus`, `away.start`, `meeting`, `dictation` |
| `source` | `button`, `mcp`, `api`, `mac`, `wispr` |
| `start`, `end` | UTC ISO-8601; `end` null for point events and running timers |
| `label` | what he was doing (claims, meetings) |
| `ref` | the event this one acts on (a stop references its start; a delete references its target) |
| `data` | JSON with source-specific details (app name, bundle id, URL, …) |
| `source_key` | unique key for imported records, so re-importing is a no-op |

How a few actions turn into events:
- **Timer:** `timer.start` (label). Stopping appends `timer.stop` with `ref` set to
  the start. Starting a new timer while one runs auto-stops the old one first.
- **Edits are new events:** deleting appends `entry.delete` with `ref` set to the
  target. Nothing is ever erased.
- **Activity:** the app posts `app.focus` on every app switch, plus a heartbeat
  every 5 min. It posts `away.start` on lock, sleep or 5 min idle. A focus segment
  lasts until the next activity event, capped at 10 min past its last heartbeat.

## API (all JSON)

- `GET /now`: running timer, current app, ongoing meeting
- `POST /timer/start {label}` · `POST /timer/stop`
- `POST /entries {label, start, end}` or `{label, minutes}` (ends now)
- `DELETE /entries/{id}` (appends a tombstone)
- `POST /observations {type, start, end?, data?, source_key?}`
- `GET /timeline?date=YYYY-MM-DD`: claims, meetings, activity, dictations for that local day
- `GET /summary?date=…`: minutes by label, minutes by app, tracked vs. untracked

## MCP tools

`what_is_rithvik_doing`, `timeline(date)`, `day_summary(date)`,
`log_activity(label, start, end)`.

## UI

- A small translucent dark pill on the right edge of the screen, on every Space. It
  shows a green dot and elapsed time while a timer runs. Click it, or press
  **⌃⌥D**, to toggle the panel.
- **Panel:**
  - current timer with a Stop button
  - "What are you doing?" field: Enter starts a timer; quick buttons log the last
    15m / 30m / 1h / 2h instead
  - a day timeline: activity lane (faint, by app), claims lane (solid), meetings.
    Drag across the timeline to label a range. Right-click a block to delete it.
  - ‹ › to move between days. Esc or clicking away hides it.

## Not in v1 (on purpose)

Window and tab titles (needs Accessibility permission), Claude Code session import,
WHOOP, calls, phone, nudges, predictions, Notion, pushing to Muse, auth (local only).

## Testing

pytest on derivation and the API, run against a temp DB. Manual smoke test of the app.

## Revision 2026-10-09 (his feedback after first use)

- **Keyboard only.** The always-visible pill is gone. ⌥ + fn (fallback ⌃⌥D) opens a small
  panel at the top-center of the screen, like Spotlight.
- **No calendar / day view in the UI.** The timeline API stays for agents.
- **One-line logging with a time window** (his choice): `client call 3:10-3:25`,
  `15m`, `2pm to 2:40`, `since 1pm`. The server parses (`daylog/parse.py`,
  `GET /parse` preview, `POST /log`), so the phone and scripts share it.
- App signed with a stable local identity (`daylog-local`), so Accessibility permission
  survives rebuilds.
- **Floating bar, Wispr Flow-style** (his ask): solid black capsule, no window chrome,
  drops from the **top**-center (bottom is where his Wispr bar lives). ⌥ + fn dropped.
- **Scroll back with ↑/↓** (his choice: logs + gaps). `GET /history` returns newest-first
  stops: entries, meetings, and untracked gaps of 10 min or more. ⏎ on a gap fills it in.
  The yellow ring marks "looking at the past".
- **⌥L opens daylog** (his pick: shorter than ⌃⌥D).
- **⌘N notes** (his ask): `POST /notes` records a moment-in-time thought, `ref` → the
  running timer, without changing tasks. Notes appear in `/timeline` (`notes`), in
  `/history` as `note` stops, and in the MCP description. Blue ring = a thought.
